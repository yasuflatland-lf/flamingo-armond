# Dev quickstart

> Part of [`frontend/CLAUDE.md`](../../frontend/CLAUDE.md). See the index for related chapters.

```bash
cp frontend/.env.example frontend/.env.local   # tweak BACKEND_URL if needed
pnpm --filter frontend dev                     # http://localhost:3000
pnpm --filter frontend build                   # production build
pnpm --filter frontend lint                    # biome check .
pnpm --filter frontend typecheck               # tsc --noEmit
pnpm --filter frontend test:e2e                # Playwright; requires Supabase + backend
```

> `typecheck` depends on `.next/types/routes.d.ts` generated by `next dev`/`next build` (Next 16 auto-generates this). Run `pnpm --filter frontend dev` or `pnpm --filter frontend build` once after a fresh checkout before typechecking.

> Pre-PR verification must run `pnpm --filter frontend build`, not just `pnpm --filter frontend test`. Vitest runs in jsdom and does not exercise the Turbopack bundler, so it cannot catch RSC ↔ client bundle boundary violations such as `next/headers` leaking into a client component (see Gotchas § "Client components must not import from RSC files that touch `next/headers`"). The build is the only check that runs the bundler against the full app graph.
