# Frontend TypeScript conventions

> Applies to: `frontend/src/**/*.{ts,tsx}`. Cross-cutting type-design rules that affect correctness, security, or testability and are non-obvious from the TypeScript docs alone.

## Rules

- [Required `string | null` over optional `?: string | null` for security-relevant or caller-deliberate props](typescript-conventions/required-string-null-over-optional-string-null.md) — Prefer required nullable props over optional nullable props for security or deliberate-caller cases.
- [JSDoc as the enforcer of "pre-sanitized" invariants when branded types are not used](typescript-conventions/jsdoc-as-the-enforcer-of-pre-sanitized-invariants.md) — Use load-bearing JSDoc to document caller-side sanitization contracts when branded types are unavailable.
- [`expect.objectContaining({ message })` is not enough — add a discriminating key](typescript-conventions/expect-objectcontaining-message-is-not-enough.md) — Add a non-`Error.prototype` key to assertions so bare-`Error` regressions fail the test.
- [TanStack Form `_handleSubmit` re-throws — chain `.catch()` on `form.handleSubmit()`](typescript-conventions/tanstack-form-handlesubmit-re-throws.md) — Swallow the re-thrown rejection at the JSX call site to avoid unhandled-promise warnings.
- [Re-throw inside TanStack Form `useForm.onSubmit` to keep `isSubmitSuccessful` correct](typescript-conventions/re-throw-inside-tanstack-form-useform-onsubmit.md) — Re-throw after logging in `onSubmit` so the form does not believe a failed mutation succeeded.
- [Radix `AlertDialogAction` closes the dialog synchronously — call `e.preventDefault()` to keep it open on failure](typescript-conventions/radix-alertdialogaction-closes-the-dialog-synchronously.md) — Call `e.preventDefault()` so the consuming component controls dialog close on success vs. failure.
- [Radix `asChild` Slot collapses a `null` child into an empty wrapper — gate at the parent](typescript-conventions/radix-aschild-slot-collapses-a-null-child.md) — Gate the wrapping container at the parent when the child can self-suppress to `null`.
- [Slot/content props use `ReactNode`, not `JSX.Element`](typescript-conventions/slot-props-reactnode-over-jsx-element.md) — `JSX.Element` rejects valid children (conditionals, arrays, strings); applies to props, not a component's return type.
- [Discriminated union over flat DTO when consumers must branch on the variant](typescript-conventions/discriminated-union-over-flat-dto.md) — Model factory outputs with a `kind` tag instead of runtime introspection of a flat DTO.
- [Positive allowlist over negative exclusion in discriminated-union narrowing](typescript-conventions/positive-allowlist-over-negative-exclusion.md) — Enumerate the variants you want, never the variants you do not want.
- [`as string` cast on regex captures under `noUncheckedIndexedAccess`](typescript-conventions/as-string-cast-on-regex-captures.md) — Use `as string` with a load-bearing invariant comment for required regex captures.
- [`router.replace` / `router.push` must propagate preserved query params explicitly](typescript-conventions/router-replace-router-push-must-propagate-query-params.md) — Re-attach already-sanitized query params via `URLSearchParams` when rewriting the URL.
- [Audit collapsed helpers for branches that lose all side effects](typescript-conventions/helper-inline-refactor-no-op-branches.md) — When inlining a multi-purpose helper, replace silent no-op branches with an explicit `console.warn`.
- [Module-level singleton `Map` keyed by entity id requires a non-empty-string guard at the entry point](typescript-conventions/module-level-singleton-map-keyed-by-entity-id.md) — Throw synchronously on empty-string ids so two unrelated callers cannot collide on `""`.
- [Re-scheduling a module-level singleton entry: commit prior immediately; warn-only on prior failure](typescript-conventions/re-scheduling-a-module-level-singleton-entry.md) — Commit the prior entry on re-schedule and route its failure to `console.warn`, not the user banner.
- [Cross-module constant references in test descriptions are silent-rot coupling](typescript-conventions/cross-module-constant-references-in-test-descriptions.md) — Name the sibling module's responsibility, not its constant identifier, in test prose.
- [`useSyncExternalStore` over `useState + useEffect` for browser-store subscriptions](typescript-conventions/usesyncexternalstore-over-usestate-useeffect.md) — Use `useSyncExternalStore` for any hook that observes a browser API and surfaces its value.
- [`next/dynamic({ ssr: false })` over a `useMounted` hook for hydration-sensitive client-only components](typescript-conventions/next-dynamic-ssr-false-over-a-usemounted-hook.md) — Skip SSR at the module-loading boundary instead of gating render with a `useMounted` flag.
- [Stabilize callback identity via `useRef` mirrors when the callback reads frequently-changing state](typescript-conventions/stabilize-callback-identity-via-useref-mirrors.md) — Mirror frequently-changing state into refs so `useCallback` identity stays stable across updates.
- [`useEffectEvent` replaces ref mirrors for Effect-owned callbacks](typescript-conventions/useeffectevent-replaces-ref-mirror.md) — Use Effect Events for observer-owned latest-value reads; keep ref mirrors only as a fallback outside Effect-owned subscriptions.
- [State ownership for high-frequency callbacks: push state down to the consumer](typescript-conventions/state-ownership-for-high-frequency-callbacks.md) — Declare per-frame state in the leaf consumer, not an ancestor, so 60 Hz callbacks do not reconcile the whole route subtree.
- [React 19 ref-as-prop preserves the generic parameter that `forwardRef` erases](typescript-conventions/react-19-ref-as-prop-generic-preservation.md) — Accept `ref?: RefObject<H | null>` as a plain prop so generic components keep their type parameter at the call site.
- [Type placement in component trees: co-locate at the deepest common ancestor directory](typescript-conventions/type-placement-in-component-trees.md) — Move shared feature types into `components/<feature>/types.ts` so low-level primitives do not import from route-level client components.
- [Derive during render instead of resetting state via a `useEffect` keyed on the trigger](typescript-conventions/derive-during-render-instead-of-resetting-state.md) — Capture a snapshot at the moment of derivation and compare during render instead of nulling state in an effect.
- [Preserve a conflict banner across a same-entity auto-refetch](typescript-conventions/preserve-banner-across-same-entity-refetch.md) — Track the last-synced id in a ref and clear the error banner only on an id change; a same-id reload (and `useFragment`'s new-ref-per-broadcast) swaps the object multiple times, so a one-shot flag fails.
- [`usePathname()` returns percent-encoded path segments — decode before interpolating into hrefs](typescript-conventions/usepathname-returns-percent-encoded.md) — Extract → `safeDecodePathSegment` → store raw → `encodeURIComponent` once at href construction; never pass the captured segment directly to `encodeURIComponent`.
- [`sticky bottom-0` over `fixed inset-x-0` for action bars inside `SidebarInset`](typescript-conventions/sticky-over-fixed-for-sidebarinset-content.md) — Sticky positioning centers relative to the inset, not the viewport, so the rail is excluded automatically; retain `pointer-events-none` outer + `pointer-events-auto` inner for scroll passthrough.
- [`aria-keyshortcuts` creates an accessibility contract — omit on disabled elements](typescript-conventions/aria-keyshortcuts-contract.md) — Values must match `KeyboardEvent.key` exactly; omit the attribute (pass `undefined`) when the button is disabled; keep the keyboard handler in the component that owns the interactive surface to avoid duplicate-action bugs.
- [`?? []` on a non-nullable GraphQL list field is dead code](typescript-conventions/null-coalesce-on-non-null-graphql-field-is-dead-code.md) — Codegen emits `T[]` for `[T!]!` fields; the null-coalescing fallback is unreachable and misleads readers into thinking the field can be null.
- [Consume the string-union enum from `@/generated/graphql`, not the runtime `enum` from `@/generated/base-types`](typescript-conventions/generated-enum-string-union-vs-enum-symbol.md) — Codegen emits two non-interchangeable symbols per enum (union type vs runtime enum-for-fixtures); type props on the union for one source of truth and no cast, key an exhaustive `Record` by string literals, and add a `noUncheckedIndexedAccess` runtime guard for the deploy-skew window.
- [Import production constants in tests — never hardcode magic numbers for boundary conditions](typescript-conventions/import-production-constants-in-tests.md) — Import the constant from the production source so boundary-condition tests track production changes automatically.
- [`toHaveBeenCalledTimes(N)` before indexing into `mock.calls[N]`](typescript-conventions/tohavebeencalledtimes-before-mock-calls-access.md) — Bound the call count before reading a specific call's arguments so a second-call regression cannot slip past the shape assertion.
- [Module-load side-effect testing via `vi.resetModules` + `vi.stubGlobal`](typescript-conventions/test-module-load-side-effect-via-reset-modules.md) — Pattern for asserting one-time load-time `console.warn` and feature-detection branches.
- [Static-grep regression-rule tests](typescript-conventions/static-grep-regression-guard-test.md) — Naming and structuring `readFileSync`-based source-shape guards (use `*-rule.test.ts`, not `*-contract.test.ts`).
- [Capture `__typename` to a local before narrowing on a discriminated union](typescript-conventions/capture-typename-before-narrowing.md) — Hoist `const typename = result?.__typename ?? null;` above the first `if` so the unknown-variant fallthrough can log the actual server discriminator instead of `undefined`.
- [Shared form components migrating to outcome unions: additive `validationError` prop, keep legacy `error`](typescript-conventions/shared-component-partial-outcome-union-migration.md) — Introduce the new prop additively so the same component can serve a promoted caller and an unpromoted caller across the per-mutation migration window.
- [Derive `optimisticResponse` types from generated mutation types — never duplicate inline](typescript-conventions/derive-optimistic-response-types-from-generated.md) — Build the synthetic optimistic payload's nested type via `Extract<Mutation["field"], { __typename: "SuccessVariant" }>["subfield"]` so schema additions and union-promotion path shifts surface at compile time.
- [JSX comments must explain why, not what](typescript-conventions/jsx-comments-must-be-why-not-what.md) — Delete layout-region labels that paraphrase class names or JSX nesting; add a comment only when removing it would cause a reader to make the wrong change.
- [React JSX interpolation is not an XSS vector](typescript-conventions/react-jsx-interpolation-is-not-xss.md) — JSX `{value}` produces a DOM text node, not innerHTML; the only React XSS vector is the raw-HTML prop, and URL/CSS contexts are separate vectors with separate mitigations.
- [Element type stability in conditional branches](typescript-conventions/element-type-stability-in-conditional-branches.md) — Keep the same root element type across all conditional branches so React does not unmount and remount the subtree on condition change.
- [Hook Application vs. Presentation layer separation](typescript-conventions/hook-application-vs-presentation-layer.md) — Extract stateful logic and network calls into a hook (Application layer); leave rendering decisions in the component (Presentation layer); never mix the two inside a single hook return.
- [Hook return values expose actions, not setters](typescript-conventions/hook-expose-actions-not-setters.md) — Return named action functions (`retryFetchMore`) instead of raw state setters (`setFetchMoreError`) so the public API describes intent, not implementation.
- [`ReadonlySet` and `PropertyKey` in hook return types](typescript-conventions/readonly-set-and-propertykey-in-hook-return.md) — Type multi-select state as `ReadonlySet<PropertyKey>` in the hook return so consumers cannot mutate the set and the key type remains structurally correct.
- [Subcomponent extraction: line-count threshold and layer separation](typescript-conventions/subcomponent-extraction-line-count-threshold.md) — Apply hook extraction first (Application layer), then view-fragment extraction (Presentation layer) when the host component remains at or above 400 lines after hook extraction.
- [Test hooks via their public surface, not their internal state](typescript-conventions/test-via-public-surface-not-internal-state.md) — Drive hook invariants through real inputs (MockedProvider rejection, user actions) rather than calling internal setters directly; a test that only exercises `useState` does not cover the hook's contract.
- [Object-first dialog title for destination-selection sheets](typescript-conventions/object-first-dialog-title.md) — When the destination object is the high-risk variable (not the verb), promote it to the visible title; this is a deliberate deviation from the verb-first convention used by single-destination sheets.
- [Composing an accessible name with an `sr-only` prefix span](typescript-conventions/sr-only-prefix-for-accessible-name.md) — Insert an `sr-only` span before the visible text to provide a full verb-plus-object accessible name without duplicating state in `aria-label`; `sr-only` clips via absolute positioning, not `display:none`, so the prefix stays in the accessibility tree.
- [An inline `<label>` collapses a `space-y-*` wrapper's gap](typescript-conventions/inline-label-collapses-space-y-gap.md) — `<label>` defaults to `display:inline`; Tailwind `space-y-*` applies margin only to block-flow siblings, so the gap is silently dropped. Fix: add `block` to the label's className.
- [Merging a field's format hint into its `<label>` shifts the hint from accessible description to accessible name](typescript-conventions/label-hint-merging-shifts-name-vs-description.md) — Inlining a short, always-relevant format rule inside the `<label>` makes it part of the accessible name, not the description; tests must switch from `toHaveAccessibleDescription` to `toHaveAccessibleName`.
- [Widening a prop from `string` to `string | ReactNode` breaks string-concatenation fallbacks](typescript-conventions/reactnode-string-coercion-in-fallbacks.md) — Template literals coerce a `ReactNode` to `"[object Object]"`; guard with `typeof title === "string"` before interpolating into an accessible description fallback.
- [Test the ARIA contract via `toHaveAccessibleName`/`toHaveAccessibleDescription`, not `textContent`](typescript-conventions/test-aria-contract-via-accessible-name.md) — `textContent` passes incidentally and does not verify `aria-labelledby`/`aria-describedby` wiring; parametrize over both UI branches (e.g. desktop Sheet vs mobile Drawer) with `describe.each` when the same prop change applies to both.
- [A thin (`h-1`) clickable bar fails the WCAG 2.5.8 target-size minimum — enlarge with transparent padding](typescript-conventions/wcag-target-size-thin-clickable-bar.md) — Use `-my-2 py-2` (negative margin + padding) to expand the click/tap target to ~20 px without changing the bar's visual position or the surrounding layout.
