# Supabase module

Provisions the Supabase project, generates the DB password, and exposes the
JWKS / pooler outputs the rest of the stack needs. Auth configuration
(`supabase_settings`) is intentionally NOT in this module — it lives in the
`settings` stack so it can be re-applied without touching the project state.
The split keeps DB password state out of the resource that operators iterate on
most often.

## Inputs

| Name | Description |
|---|---|
| `project_name` | Display name for the project. |
| `organization_id` | Owning Supabase organization. |
| `region` | Region slug (e.g. `ap-northeast-1`). |

## Outputs

| Name | Description |
|---|---|
| `project_ref` | Project slug used in `https://<ref>.supabase.co`. |
| `project_url` | Full base URL. |
| `anon_key` | Public-safe API key (sensitive in state). |
| `db_url` | Session-mode pooler DSN. |
| `db_password` | Generated DB password (sensitive). |
| `jwks_url`, `jwt_issuer`, `jwt_audience` | JWT validation values for backend. |

## Notes

- `supabase_project` carries `lifecycle { prevent_destroy = true }`. Removing
  the project drops its database. Disable the guard explicitly to destroy.
- The DB password is generated by `random_password`. To rotate, run
  `terraform apply -replace=module.supabase.random_password.db` from the
  `initial` stack directory.
